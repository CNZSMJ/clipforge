# 从分镜到关键帧：画面工作台

适用：`CNZSMJ/clipforge` 的 `feat/fal-migration`，2026-09-17。
业务基线：`626614086f15eff6d0a52c73630dbc3e2d750eac`；本轮源代码快照：`49d86dc02500bbeb8b962cc168026ecda71ab6b7`。

## 产品目标与边界

用户不用理解 Visual Bible、reference routing 或填写 JSON。素材页提供「统一设定 → 确认场景样片 → 逐镜检查 → 生成视频」路径。原图、库存、用户上传依然是有效素材来源，不为“统一AI画风”强迫全部重生。新流程优先使用现有 Fal 端点和均衡文本/视觉模型，不更改用户的模型、Key 或项目脚本。

这次交付是已接线的提示词编译、参考输入、持久化、候选审核与UI流程，不是仅有提示词方案。自动化测试证明这些规则和状态流正确接入；没有真实收费出图对照、成片盲评或抽卡成功率实测，不能声称人体绝不会错误、跨镜完全一致或一次出图必定可用。

## 研究依据如何转为实现

1. Fal 的 Sunburst Edit API 真实接收 `image_urls`，应使用上传返回的URL，不是把图片文件名写进文字。工作台把编辑底图、商品、人物、场景、画风、构图参考编号与真实数组顺序绑定。最多8张相关参考是本工作流的成本/审核边界，不是该模型官方16张上限。能力不匹配在付费前拒绝，不截断参考图。
2. Runway 官方参考工作流展示用草图/标注约束视线、构图与对象位置，也区分风格引用与主体引用。这里实现的是用户上传已有姿态/构图草图并绑定到当前镜头，不是假装已经接入 ControlNet、姿态估计或像素级硬约束。
3. BFL 的多参考编辑说明以图片索引指定主体与对象用途。这里借鉴角色分工原则，不把 BFL 的参数或参考数量直接套到 Fal 的其他端点。

## 使用路径

在素材页打开画面工作台。选择或继承全片媒介、色板、默认光线和材料表现；快捷项包括自然生活、产品棚拍、极简三维、平面插画，均可修改。原有项目约束仍作为输入，已批准的工作台媒介优先于旧分镜里随意出现的风格词。

上传参考时选择用途：商品外观、人物身份、当前场景、全片画风、当前镜姿态/构图。人物使用姓名选择；是否出镜按镜头勾选，不根据画外声音强行加脸。场景按分组复用，不默认所有镜头在同一个房间。图像存入本项目后经路径和实际媒体校验，不能通过设置表单伪造别的项目图片或审核记录。

「整理全片画面方案」是一次明确确认的文本模型调用，针对全部已选分镜生成单帧时刻、机位、站位、视线、双手分工、接触/支撑、物体状态与场景分组。它不重写剧情或台词，返回可编辑草稿；用户保存才生效。也可免费手动填写，不强制购买整理服务。没有单帧时刻不能付费生图。

先预览一镜：显示实际模型、参考缩略图与编号、完整实际提示词及缺失参考提醒；确认才提交1张图片。新图是未选中的候选，保留旧图。不满意时输入「只修哪里」：当前候选作为第一张编辑参考，保留身份/画风/布局的约束，修改指定关系。此为参考驱动的定向编辑，不是已实现遮罩绘制，也不保证其他像素完全不变。

人工确认候选是免费操作；可一起设为本场景样片。其他镜头仅引用对应场景；新样片不会把原来的动作进度复制给其他镜头。调整全局风格会使所有相关审核过期；场景、镜头、参考改变仅使依赖它们的镜头过期。改动不会删除已有图片。旧图需要明确人工复核后才重新确认。

「生成剩余分镜」仅处理没有候选、没有待恢复任务的AI镜头。目标场景必须已有样片，每次最多12张、默认6张，顺序逐镜调用，失败即停止；停止按钮只阻止后续提交，不伪称已撤销当前云任务。所有新结果仍需人工确认。

可选「智能检查」只在用户确认后调用一次视觉模型。它把候选与相关参考一起检查，关注主体、媒介、操作朝向、手、接触、支撑、尺度与当前动作瞬间。当前图不会作为自己的质检参考；同图同设定的报告缓存，关键失败不能用漂亮光线抵消。AI检查是辅助意见，缺证据应人工复核；用户可明确承担风险覆盖拒绝结果。

已启用工作台的项目，在逐镜视频、整片和本地合成入口核对当前图片审核及实际输入。不能通过旧生图API绕过新工作流，也不会让旧九宫格自动覆盖审核图；对应入口会提示改用已确认样片拓展。未启用工作台的历史项目保留原行为。确认图片不自动购买视频；素材页原来的生图后自动动效已移除。

## 图像提示词而不是脚本复述

编译顺序：来源身份/人物边界 → 全片媒介与场景 → 本镜单帧规格 → 旧脚本内容。单张图表现一个明确瞬间，而非“走过去、开机、倒奶、端杯、回头微笑”整段过程。

状态与固定特征分离：商品几何/原有标识/材质、人物身份/衣服、场景固定布局不随镜头重设；杯中液量、开合和持物等跟随步骤变化。场景光源和家具位置使用世界坐标；机位改变会改变投影，不能为保持每镜“画面左边”而镜像整个房间。

人物操作用关系而非空泛的“解剖正确”：躯干与髋部朝任务方向、视线看当前操作目标、左右指演员自身、每只手承担一个相容职责、手指接触正确按钮/把手、杯子有托盘支撑、物体可触及且大小合理。冲咖啡按当前步骤处理，不同时拧手柄、接咖啡、开蒸汽和倒奶。无人模式不为了“功能演示”增加手；有意非物理动画仍遵守用户明确的媒介意图。

参考角色相互隔离：商品图不复制原背景，人物图不复制姿态，场景图不复制旧动作状态，画风图不引入其人物/地点，草图不把箭头文字画入最终图。原商品标识保留；字幕、价格和精确UI由后期完成。

## 类型适配

| 类型 | 本轮生图执行重点 |
|---|---|
| 痛点种草 | 阻碍和被比较条件清楚，不编造损伤/焦虑 |
| 场景安利 | 具体生活空间与必要道具，不自动变豪华广告棚 |
| 对比测评 | 样本身份、左右、尺度、光线匹配，未知结果不编造 |
| 剧情故事 | 道具回现与当前因果节点；单镜不表现全部事件 |
| 情景短剧 | 角色站位、行动轴线、说话者与听者、一个主要互动 |
| 反转剧场 | 同一线索的遮挡/揭示进度，不更换对象制造反转 |
| 街头采访 | 麦克风归属、合理伸手距离、双方朝向，不造证言图 |
| 开箱测评 | 封条/盖/配件数量与当前步骤连续，不复原包装 |
| 物品拟人 | 声音拟人，外观不长嘴、眼睛、四肢 |
| 达人口播 | A-roll才看镜头；B-roll看操作，不把旁白人塞进特写 |
| 知识科普 | 一个概念、可核对的结构关系，装饰不替代证据 |
| 情感故事 | 当前选择与复现道具，人物/物件身份稳定 |
| 生活方式 | 真实步骤、工具、材料、用量，不混拼不同进度 |
| 励志内容 | 可见的有限进展，不强制奔跑/登顶模板 |
| 旅行风光 | 地点与时间可信；AI示意不得当纪录影像 |

新主题脚本持久化原来的5类主题标签，避免全部存成 custom 后丢失针对性。旧记录不猜测标签。原图/库存镜头变成AI候选需要额外勾选，不能让模拟图冒充实测证据。

## 成本、恢复与工程约束

- 全局设定/草稿保存、预览、人工确认、已有任务恢复不新增推理请求。整理全片是一次文本调用，智能检查是一次视觉调用，均单独确认。不默认多轮brainstorm、每镜自评或自动四图抽卡。
- 图片质量使用所选端点的既有默认，不自动提高到最高档；请求数量强制1，屏蔽可以覆盖参考/模型/提示词的额外参数。种子不是跨镜身份锁；模型不支持时不宣称生效。
- 未得到精确报价会明确显示未知价格；输出尺寸、质量和参考都影响实际账单。次数上限不是美元硬上限，原视频spendCap不被描述为LLM或图片硬预算。
- 先上传参考，再持久化付费意向，再仅提交一次生成POST；确认回执后立刻存任务ID再轮询。超时/下载失败恢复原任务，不重新购买。进程内合并和SQLite事务阻止同镜并行重复购买；这不是供应商与本地数据库的分布式exactly-once事务。
- 受理状态不明且没有request_id时阻止重提，提供人工核对Fal历史并绑定回执，或明确确认“未受理”解除阻塞。不会依据404自行认定未收费。必须核对模型、时间与请求内容。
- 下载、有效图像检查与候选持久化复用现有可靠传输层；结果URL/回执先落库，保存失败可恢复。不把半文件用于后续视频。
- 当前审核生图支持已验证的Fal内置端点。其他供应商和未验证自定义端点不会被悄悄换平台；上传素材仍可用，但该端点需要接入契约后才能使用工作台生成。

## 存储与验收

Drizzle迁移 `0020_keyframe_workspace.sql` 新增项目工作台和生成意向表，并给脚本增加可空主题标签。JSON包含版本和逐镜指纹；普通设置保存不能伪造审批。版本检查防止多窗口覆盖；场景样片固定与审批是一个事务。保留持久数据目录，更新前备份数据库与素材。迁移不会重写历史图片或发起生成。

代码入口：`keyframe-direction.ts`、`keyframe-store.ts`、`keyframe-service.ts`、`api/project/[id]/keyframes/route.ts`、`components/keyframes/keyframe-studio.tsx`。视频、整片、任务恢复与合成入口均接入审核约束。

回归：`keyframe-direction.test.ts`、`keyframe-workflow.test.ts`、`keyframe-studio.test.ts`，分别覆盖编译与15类规则、真实SQLite/路由且模拟收费边界、React交互与收费确认。CI还执行真实Chromium浏览器的上传、保存、预览、取消、确认/固定样片、刷新持久化与手机宽度检查；浏览器使用明确标记的有效测试图片，不是模型出图。

最终结果以对应提交的CI日志和产物为准，不能引用上一轮的测试通过数替代本轮。上线后的视觉验收应在固定brief、相同模型/质量/尺寸/参考/预算下比较首张可用率、身份/风格/物理错误率与每张可用图的总费用；本轮没有编造这些指标。
