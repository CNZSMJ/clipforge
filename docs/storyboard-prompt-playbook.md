# 分镜提示词：类型、创意、连续性与执行

2026-09-17；`CNZSMJ/clipforge`，仅 `feat/fal-migration`。业务基线 `724557b1cae2185020360e56d2276953697b29df`。

## 真实类型与研究方法

项目有 10 种商业叙事（另有 custom）、5 种无商品主题风格，以及与叙事正交的 4 种制作模式。商品品类为美妆、食品、家居、服装、数码。模板库的商品展示、真人讲解、剧情叙事、生活种草、促销转化、创意视觉是组合入口，不是额外六套引擎。项目介绍片、企业品牌片、长篇连续短剧目前不是独立一级类型。

以下策略是依据一手方法资料、针对当前代码的编导与工程设计，不是 15 个类型已完成商业 A/B 验证。只注入当前类型，不同时发送所有规则。

| 类型 | 创意与有效性 | 跨镜头及视觉执行 |
|---|---|---|
| 痛点种草 | 一次具体任务的微小阻碍，以可见变化证明 | 同条件匹配构图，阻碍→介入→结果，不以焦虑/假效果替代依据 |
| 场景安利 | 一个具体时段的生活需求，仪式或收尾回看 | 定位→动作→细节→生活结果，物品、用量、时间连续 |
| 对比测评 | 一个购买问题、一项比较维度 | 固定左右/光照/单位；没有数据不编竞品结果 |
| 剧情故事 | 愿望→障碍→选择→可见后果 | 用道具复现与首尾构图呼应，动机、身份和动作状态可追踪 |
| 情景短剧 | 不同目的碰撞，以行动改变局势 | 说话者分配、正反打、反应镜和道具交接；无人物模式用画外对白 |
| 反转剧场 | 先合理误读，再用公平铺垫的线索重释 | 揭示改变理解、不偷换对象或临时新增商品能力 |
| 街头采访 | 回答决定追问/演示，不轮流念广告 | 空间定位与麦克风位置连续；虚构采访明确演绎，不假装路人证言 |
| 开箱测评 | 围绕一项真实疑问安排揭示顺序 | 封条→开盖→配件→上手观察；一镜一步，包装不能复原 |
| 物品拟人 | 个性来自商品声音和声画反差 | 不长嘴/眼/四肢，不为配音加真人；几何、朝向、状态稳定 |
| 达人口播 | 明确观点＋具体依据＋适用边界 | 稳定 A-roll、准确 B-roll；旁白不意味着每镜都有人脸 |
| 知识科普 | 可验证问题→预测→观察→解释→应用 | 每镜一个概念，变量颜色/单位固定，声画互补而非装饰堆砌 |
| 情感故事 | 具体选择与后果，物件/未完成动作承载情绪 | 允许无声停顿；同人需同源素材，不用不同脸冒充同一人 |
| 生活方式 | 一个空间内的一次具体习惯或过程 | 准备→操作→结果，材质/光影服务过程，工具和进度不跳变 |
| 励志金句 | 一个困难、一项可实行的小动作 | 同一动作的阻力与有限进展，不默认登顶混剪或假名言 |
| 旅行风光 | 路线、时间线或感官线索选一种 | 定位→接近→地方细节→回望；真实地理、季节和素材来源 |

主要来源：TikTok Creative Codes 的商业结构/声音/移动构图；Google ABCDs 的信息聚焦、声画支持与行动目的；Pixar/Khan Academy 的愿望/障碍/选择；Brame 的教育视频认知负担与声画互补；Adobe 的场景轴线；Runway 的首帧与运动提示分工。借鉴原则，不借用来源提升百分比作为本项目结果，不把 Runway 参数当 Fal 接口契约。

## 实际修改

`storyboard-direction.ts` 分类型生成协议，`storyboard-render-direction.ts` 统一渲染边界。没有额外 brainstorm、自评或修稿调用；在已有调用里决定一个观众目标、核心命题、主要创意机制和视觉记忆点，直接输出既有 JSON。

规则优先级：事实与参考素材 → 制作模式 → 用户媒介与项目视觉规范 → 类型 → 品类 → 平台编辑建议。自定义要求、英文输入、参考片节奏与既有表现反馈保留，但示例与反馈不覆盖明确要求。主题去掉商业促销结构；平台建议不再声称秘密算法权重。

固定锚包括人物身份/衣着、商品几何/配色/标识及场景内布局/光线；变化状态包括开合、持物、数量、液面和动作进度。description 写“起始状态→一个主动作→结束状态”，prompt 描述动作开始前的定格和必要锚，camera 服务该镜的信息。明确换景允许建立新场景，而非强迫全片同一房间。

新增可选 `Shot.speakerVisible` 布尔值，经解析、现有 shots JSON 和素材行透传，无 SQL 新列。`characterId` 保留声音身份，不自动代表可见人脸。显式 false、物品拟人及禁露脸模式不触发对镜口型；旧脚本在模式边界内保留回退。

`product_closeup` / `graphic_montage` 不加人物或手；`scene_demo` 仅脚本需要的手/背影、无脸；`live_presenter` 按镜放人。主题继承的商业默认 mode 不当成人物禁令。原图只做裁切、平移缩放与文字层，不假装拆封或生成未知背面。尊重明确的动画/模型/展陈媒介。

九宫格/整片不再默认手机 UGC、全镜露脸或同一房间；接收相同项目上下文，保持参考素材顺序和预览/付费提示词一致。逐镜运动保留完整动作描述，不截断关键结束状态、不被默认手势替换；项目全局动作/运镜不覆盖已批准逐镜动作。原生对白不再与“无人声”要求冲突。首尾帧、上传 URL、队列和任务恢复逻辑未改。

审稿包含无声视觉镜及类型上下文，保护合理慢节奏/诗性表达；跨镜矛盾给整组建议。解析层拒绝把空旁白填成新台词，翻译保留留白，全无声脚本不调用翻译模型。修改 description 清除过期派生 prompt，改台词/机位或未实际改变描述时不清除。不会自动删除或重购既有素材。

## 成本与验证

不改当前均衡模型、Key、网关或调用预算，没有自动付费测试。固定输入比较 system+user 的 Unicode 字符数：商业 10 类型平均 8,039.6→7,640.3（-5.0%），主题 5 类型 2,876.2→3,288.4（+14.3%）。商业删重复长示例，主题补连续性；这是字符而非 token/账单，不保证每次更便宜。

本地 TypeScript、生产构建通过；Lint 0 错误、24 个既有警告；147 文件、1,611 项测试通过。两份新测试文件包含 82 项，覆盖 10×4 类型/模式、5 个主题、SDK 请求体（模拟网络）、真实路由与 SQLite、声音/出镜、动作/视觉规范、预览/付费同提示词及静默保护。发布仍须 GitHub Actions 校验精确源码树，并以其实际结果为准。

未执行真实收费 Fal 生成、实际成片盲评或投放测试。提示词正确接入不等于人物永不漂移或转化率提升。免费库存不能凭文字保证同一人物/地点。静态零 LLM 的 `hook-variants.ts` 仍是模板机制草稿，例句需人工事实审核；本次不能被描述为所有静态模板已成为定制可投放成片。旧主题脚本存为 custom 时审稿不能可靠还原原五类标签。历史脚本/素材不会自动重写。

建议验收：每类型固定一份 brief，先脚本盲评，再只买关键/有分歧的候选成片。两位评审按创意具体性、目标有效性、因果兑现、连续性、可执行视觉各 20 分；事实、人物边界、关键状态错误先否决，不用漂亮画面抵消假证据。该量表为本项目建议，不是学术标准。真实出片检查参考主体、关键帧、动作、音画；商业指标另做同流量条件对照。
